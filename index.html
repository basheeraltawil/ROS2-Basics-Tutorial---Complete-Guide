Introduction to ROS2 Basics

Welcome to this comprehensive tutorial on ROS2 basics. This guide will walk you through the fundamental concepts of creating a ROS2 package, with a focus on practical implementation and best practices.

ROS2 (Robot Operating System 2) is a set of software libraries and tools that help you build robot applications. From drivers to state-of-the-art algorithms, and with powerful developer tools, ROS2 has what you need for your next robotics project.

In this tutorial, we'll explore:

  • The structure of a ROS2 package and why it matters
  • How to define dependencies and metadata in package.xml
  • Configuring Python packages with setup.py
  • Using YAML files for parameter configuration
  • Writing node scripts that utilize parameters effectively
  • Creating launch files for easy execution
  • Building and running your ROS2 package

Tip: This guide assumes you have basic knowledge of ROS2 and have it installed on your system. If not, please check the official ROS2 installation guide first.

Package Structure

A well-organized package structure is crucial for maintainability and collaboration in ROS2 development. The structure helps separate concerns and makes it easier to locate files as your project grows.

Our ROS2 basics package follows this structure:

ros2_basics/ - Root directory of our package config/ - Directory for configuration files launch/ - Directory for launch files ros2_basics/ - Python package directory package.xml - Package manifest file setup.py - Python setup script setup.cfg - Setup configuration file
1

Creating the Package

To create a new ROS2 package, use the following command in your terminal:

ros2 pkg create --build-type ament_python ros2_basics

This command creates the basic package structure with all necessary files. The --build-type ament_python flag specifies that we're creating a Python package.

2

Understanding the Structure

Each directory and file has a specific purpose:

  • config/: Contains YAML configuration files for parameters
  • launch/: Contains Python launch files to start nodes
  • ros2_basics/: The main Python package with node implementations
  • package.xml: Defines package metadata and dependencies
  • setup.py: Configures Python package installation
  • setup.cfg: Additional setup configuration

package.xml - Package Manifest

The package.xml file is a crucial component of any ROS2 package. It serves as the package manifest, containing metadata, dependencies, and other essential information about your package.

View the complete package.xml file on GitHub
1

Basic Metadata

The package.xml starts with basic metadata about your package:

  • name: The name of your package (must match the directory name)
  • version: The current version of your package
  • description: A brief description of what your package does
  • maintainer: Information about the package maintainer
  • license: The software license for your package
2

Dependencies

Dependencies are categorized into different types:

  • build_depend: Packages needed at build time
  • exec_depend: Packages needed at execution time
  • test_depend: Packages needed for testing
  • depend: Shorthand for both build_depend and exec_depend

For our basic package, we depend on:

  • rclpy: The ROS2 Python client library
  • std_msgs: Standard message types
  • sensor_msgs: Sensor-specific message types
  • launch and launch_ros: For launch file functionality
3

Export Section

The export section specifies build system information. For Python packages, we use:

<build_type>ament_python</build_type>

This tells ROS2 that this is a Python package using the ament build system.

setup.py - Python Setup Script

The setup.py file is used to configure the installation of your Python package. It defines entry points, data files, and other package properties.

View the complete setup.py file on GitHub
1

Basic Configuration

The setup.py file begins with basic package information:

  • name: Package name (should match package.xml)
  • version: Package version
  • packages: List of Python packages to include
  • data_files: Non-Python files to include (config, launch files)
2

Data Files

The data_files section is crucial for including non-Python files in your package:

('share/ament_index/resource_index/packages', ['resource/' + package_name])

('share/' + package_name, ['package.xml'])

(os.path.join('share', package_name, 'config'), glob('config/*.yaml'))

(os.path.join('share', package_name, 'launch'), glob('launch/*.launch.py'))

These lines ensure that your configuration files, launch files, and package manifest are installed to the correct locations in the ROS2 workspace.

3

Entry Points

Entry points define the executables that your package provides:

'console_scripts': ['basic_node = ros2_basics.basic_node:main']

This creates an executable named basic_node that runs the main function in ros2_basics/basic_node.py.

Tip: After modifying setup.py, you need to rebuild your package for changes to take effect:

colcon build --packages-select ros2_basics

Configuration Files

YAML configuration files allow you to define parameters externally, making your code more flexible and maintainable. Parameters can be changed without modifying the source code.

View the config.yaml file on GitHub
1

YAML Structure

ROS2 parameter files use a specific YAML structure:

/**:

ros__parameters:

The /** wildcard applies the parameters to all nodes, while ros__parameters is the namespace for ROS2 parameters.

2

Parameter Types

ROS2 supports various parameter types:

  • Strings: Text values enclosed in quotes
  • Numbers: Integer or floating-point values
  • Booleans: true or false values
  • Arrays: Lists of values in square brackets

In our config file, we use all these types:

node_name: "ros2_basics_node" # String

update_rate: 2.0 # Float

enable_logging: true # Boolean

text_color: [255, 200, 50] # Integer array

3

Using Parameters in Code

To use parameters in your node, you need to:

  1. Declare the parameters with default values
  2. Retrieve the parameter values
  3. Use the values in your application logic

Parameters can be loaded from the command line, launch files, or YAML config files.

Warning: Be careful with parameter names. They are case-sensitive and must match exactly between your code and config files.

Node Script

The node script contains the main logic of your ROS2 application. It defines the behavior of your node, including publishers, subscribers, services, and parameter handling.

View the basic_node.py file on GitHub View the utils.py file on GitHub
1

Node Structure

A typical ROS2 node has this structure:

  1. Import necessary modules
  2. Define the node class that inherits from Node
  3. Initialize the node in the constructor
  4. Declare and retrieve parameters
  5. Create publishers, subscribers, timers, etc.
  6. Define callback functions
  7. Implement the main function to initialize and spin the node
2

Parameter Handling

Parameters are declared using declare_parameter or declare_parameters:

self.declare_parameters(namespace='', parameters=[('param_name', default_value), ...])

Values are retrieved using get_parameter:

self.param_name = self.get_parameter('param_name').value

This approach allows parameters to be set from various sources (code defaults, config files, command line).

3

Module Organization

For better code organization, we separate utility functions into a different module (utils.py):

from .utils import BasicUtils

This keeps the main node script focused on ROS2-specific functionality while moving helper functions to a separate file.

Tip: Use meaningful names for your nodes, topics, and parameters. This makes your code more readable and easier to debug.

Launch Files

Launch files allow you to start multiple nodes and configure them with specific parameters. They are written in Python and provide a flexible way to initialize your ROS2 system.

View the ros2_basics.launch.py file on GitHub
1

Launch File Structure

A typical launch file contains:

  1. Imports from the launch and launch_ros modules
  2. A function named generate_launch_description()
  3. Launch argument declarations
  4. Node definitions
  5. A returned LaunchDescription containing all elements
2

Launch Arguments

Launch arguments allow you to parameterize your launch files:

node_name_arg = DeclareLaunchArgument('node_name', default_value='ros2_basics_node')

These arguments can be passed when starting the launch file:

ros2 launch ros2_basics ros2_basics.launch.py node_name:=my_custom_name

3

Node Definitions

Nodes are defined using the Node class from launch_ros.actions:

basic_node = Node(package='ros2_basics', executable='basic_node', parameters=[config_file])

Key properties include:

  • package: The name of the package containing the node
  • executable: The name of the executable to run
  • name: The name to give the node (can override the default)
  • parameters: List of parameter files or dictionaries
  • remappings: Topic or service name remappings

Tip: Use launch files to set up complex systems with multiple nodes. They're much more flexible than starting each node individually.

Building and Running

This section covers the practical steps to build and run your ROS2 package, including common commands and troubleshooting tips.

1

Building the Package

To build your package, navigate to your workspace root and run:

colcon build --packages-select ros2_basics

The --packages-select option builds only the specified package, which is faster when you're working on a single package.

After building, source the setup file to make your package available:

source install/setup.bash

You may want to add this to your .bashrc file for convenience.

2

Running the Node

You can run your node in several ways:

Direct execution:

ros2 run ros2_basics basic_node

With parameters:

ros2 run ros2_basics basic_node --ros-args -p update_rate:=5.0 -p message_text:="Custom message"

Using a launch file:

ros2 launch ros2_basics ros2_basics.launch.py

3

Inspecting the System

ROS2 provides several tools to inspect your running system:

List nodes:

ros2 node list

List topics:

ros2 topic list

View parameters:

ros2 param list

ros2 param get /ros2_basics_node update_rate

Monitor node output:

ros2 topic echo /basic_topic

4

Troubleshooting

Common issues and solutions:

Package not found: Make sure you've sourced your workspace (source install/setup.bash).

Parameters not loading: Check that the config file path is correct in your launch file.

Node not running: Check the node executable exists in install/ros2_basics/lib/ros2_basics/.

Tip: Use ros2 doctor to check your ROS2 setup for common issues and misconfigurations.
